문제 제기

우리는 아직 일어나지 않은 사건의 가능성을 어떻게 판단할까?

익숙한 방식여론조사 · 전문가 전망 · 뉴스 · 커뮤니티 분위기를 참고함
새로운 질문사람들이 자신의 예상에 실제 돈을 걸게 하면 그 판단이 더 강하게 드러나지 않을까?

Prediction Market의 출발점은 베팅 서비스가 아니라 미래 사건에 대한 집단적인 판단을 가격으로 모을 수 없을까라는 질문임

출처: FP RESEARCH · 예측시장이란 무엇인가
쉬운 정의

Prediction Market은 미래 사건의 결과를 거래하고, 그 과정에서 시장의 예상이 가격으로 나타나는 시장임

예시 시장

“2026년 안에 BTC가 150,000달러를 넘을까?”

YES / NO 계약이 거래됨

현재 가격

YES = $0.70

시장에서는 이 사건의 가능성을 대략 70% 수준으로 보고 있다고 읽을 수 있음

누군가가 확률을 발표하는 것이 아니라 거래를 통해 가격이 형성되고 그 가격이 확률처럼 읽히는 구조임

출처: FP RESEARCH · Polymarket Docs
왜 가격이 확률처럼 보일까?

YES 계약의 지급 구조를 보면 $0.70이 왜 약 70%로 읽히는지 이해할 수 있음

먼저 계약의 구조

YES 계약 1개

사건 발생 → $1 지급

사건 미발생 → $0 지급

그렇다면 70%라고 생각한다면?

비슷한 상황이 10번 반복된다고 단순화

약 7번은 $1 지급 · 약 3번은 $0 지급

총 지급액 약 $7 → 계약 1개의 기대가치 약 $0.70

기대가치p × $1 + (1-p) × $0 = $p

따라서 위험중립적이고 거래비용 등이 없는 단순한 상황에서는 YES 계약의 적정가격 $0.70 ↔ 사건 발생확률 약 70%로 연결해 해석할 수 있음

실제 시장가격에는 유동성·수수료·참여자 구성·위험선호 등도 영향을 주므로 가격 = 객관적인 진짜 확률이라고 이해하면 안 됨

출처: FP RESEARCH · IEM 관련 연구
Polymarket 화면에서는 어떻게 보일까?

화면에 보이는 확률은 주문장의 대표가격이고, 실제 체결가격은 Bid·Ask에 따라 달라질 수 있음

① 표시 가격보통 최고 Bid와 최저 Ask의 중간값으로 표시됨
② 실제 매수즉시 매수하면 보통 Ask 가격에 체결됨
③ 실제 매도즉시 매도하면 보통 Bid 가격에 체결됨

예: Bid $0.34 · Ask $0.40이면 화면에는 약 $0.37 = 37%가 보여도, 실제 매수는 $0.40 · 매도는 $0.34가 될 수 있음

출처: Polymarket Docs · Prices & Orderbook
예측시장에서는 실제로 어떻게 거래할까?

사용자는 시장가격과 자신의 판단을 비교해 포지션을 잡고, 다른 참여자와의 거래를 통해 가격이 계속 바뀜

① 시장 선택“BTC가 2026년 안에 $150K를 넘을까?”
→
② 현재 가격 확인YES $0.70 · NO $0.30
→
③ 내 판단과 비교철수: “나는 80%라고 봄”
→
④ 포지션 선택시장보다 높게 보면 YES, 낮게 보면 NO 매수
⑤ 주문 체결다른 참여자의 주문과 Order Book에서 매칭
→
⑥ 가격 변화새 정보와 매수·매도가 계속 반영됨
→
⑦ 중간 선택계속 보유하거나 시장가격에 다시 매도 가능
→
⑧ 결과 확정승리한 포지션은 $1, 패배한 포지션은 $0
예: 철수의 판단시장 YES = 70%인데 철수는 실제 가능성을 80%라고 판단 → $0.70은 상대적으로 싸다고 보고 YES 매수
그다음에는?YES가 $0.82로 오르면 중간에 팔아 수익을 확정할 수도 있고, 끝까지 보유해 최종 결과에 따라 $1 또는 $0을 받을 수도 있음

예측시장의 가격은 누가 정해주는 숫자가 아니라, 서로 다른 판단을 가진 참여자들의 주문이 계속 체결되면서 만들어지는 시장가격임

블록체인은 Prediction Market의 원리를 만든 것이 아니라 거래·담보·정산 인프라를 재구성함

블록체인은 예측시장을 어떻게 구현할까?

Polymarket을 사례로 보면, 주문은 오프체인에서 빠르게 매칭하고 포지션·정산은 블록체인 위에서 처리함

앞 장표의 구조를 실제 서비스에 대입해보면 Polymarket이 대표적인 블록체인 기반 구현 사례임.

즉 Polymarket은 예측시장이라는 원리를 새로 만든 것이 아니라, 그 시장을 Wallet·Token·Smart Contract로 구현한 하나의 사례임

그렇다면 블록체인이 꼭 필요할까?

같은 예측시장도 중앙화 거래소 방식과 블록체인 기반 방식으로 구현할 수 있음

비교 이유: Polymarket과 Kalshi는 둘 다 미래 사건의 YES·NO 계약을 Order Book에서 거래하지만, 포지션과 정산을 관리하는 인프라가 다름.

그래서 Prediction Market은 도박과 뭐가 다를까?

도박과 닮은 점

  • 미래의 불확실한 사건에 돈을 검
  • 맞으면 수익, 틀리면 손실
  • 참가자가 결과를 직접 통제하지 못하는 경우가 많음

Prediction Market이 강조하는 차이

  • 참여자 거래로 시장가격이 형성됨
  • 가격이 집단적인 확률 정보처럼 활용될 수 있음
  • 시간에 따라 기대 변화 데이터가 축적됨

따라서 Prediction Market에는 사행적 성격과 가격발견·정보집계 기능이 동시에 존재한다고 보는 편이 정확함

기존 카드 결제는 아주 작은 금액을 매우 자주 결제하는 구조에서 비용 부담이 커질 수 있음

예: 1회 10원 API 호출Agent가 새로운 유료 API를 호출할 때마다 10원씩 독립적으로 결제한다고 가정

따라서 10원짜리 서비스를 호출할 때마다 별도의 카드 거래로 결제하는 방식은 토스페이먼츠 기준 최소 결제금액보다 작아 성립하지 않음. 그래서 실제 API 서비스는 구독·선불 Credit 등으로 여러 호출을 묶는 방식이 흔함

토스페이먼츠의 공개 정책을 이용한 국내 사례임. 모든 카드사·PG사가 동일한 최소 결제금액이나 수수료율을 적용한다는 뜻은 아님

카드 vs Stablecoin

블록체인 결제의 강점은 돈의 이동과 사용 조건을 같은 코드 안에서 연결할 수 있다는 점임

단순한 자동결제

“매달 10달러 결제”처럼 미리 정해진 결제를 자동으로 실행

기존 카드·계좌에서도 충분히 가능

블록체인 기반 결제

자산 이전을 코드로 정한 조건·권한과 직접 연결하기 쉬움

조건이 충족되면 결제, 아니면 실행하지 않도록 설계 가능

예시 “하루 최대 10 USDC · 승인된 서비스만 · 일정 금액 이상은 사람 승인” 같은 규칙과 결제를 연결

즉 블록체인 결제의 특징은 자동결제 자체보다, 결제에 사용 조건과 권한 규칙을 함께 붙이기 쉽다는 점임

Balance Abstraction은 여러 체인에 흩어진 잔액을 하나처럼 인식·사용하게 하고, 필요한 자산 이동은 시스템이 뒤에서 처리하도록 만드는 방식임

Gas Abstraction

Gas를 위해 체인마다 별도의 토큰을 준비해야 하는 불편을 줄일 수 있음

현재 문제USDC는 있어도 Ethereum에서는 ETH, Solana에서는 SOL이 필요할 수 있음
Gas Abstractionnative token을 직접 준비해야 하는 부담을 줄이는 방식
예시사용자에게 ETH가 없어도 서비스가 Gas를 대신 내도록 설계 가능

서비스를 쓰기 전에 Gas Token부터 사야 하는 마찰을 줄이는 것이 핵심임

Chain Abstraction이 되면 Bridge는 사라질까?

Chain Abstraction이 되어도 Bridge 자체가 없어지는 것은 아님

뒤에서는Bridge나 여러 체인을 연결하는 시스템이 실제 자산·메시지 이동을 계속 처리함
사용자에게는서비스가 경로를 대신 선택해 Bridge를 직접 찾고 고르는 과정이 덜 보임

달라지는 것은 인프라의 존재가 아니라 사용자 경험임. 사용자는 이동 과정보다 최종 결과에 집중하게 됨

Before vs After

좋은 Chain Abstraction은 사용자가 결과에 집중하게 하고 내부 라우팅은 서비스가 처리하게 만듦

Before

Network 변경 → Bridge 탐색 → Gas 준비 → DEX 선택 → Swap

After

“100 USDC로 ETH 사고 싶음.”

시스템이 Chain·Bridge·Gas·Swap 경로를 뒤에서 처리

사용자는 결과에 집중하고, 인프라는 뒤에서 작동하는 방향이 Chain Abstraction의 핵심 UX임
